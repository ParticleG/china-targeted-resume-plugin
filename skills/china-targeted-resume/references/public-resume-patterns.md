# Public Resume Pattern References

These public examples are pattern references, not candidate evidence and not text sources to copy. Reuse only the presentation rule, then materialize it from the candidate's owning evidence.

## Yin Mingzhuo — systems, database, and open-source engineering

- Public resume: https://resume.ymzymz.me/resume-zh.pdf
- Useful patterns: precise personal-versus-team contribution verbs; benchmark population and comparison scope; verifiable open-source roles, papers, and project links; enough technical detail to support interview follow-up.
- Adaptation rule: retain contribution percentage, benchmark environment, stage, and qualifier when present in the candidate source. Use two pages only when verified evidence supports the density.
- Do not copy: exceptional credentials, publication status, performance numbers, employer names, or the example's dense page budget.

## Liang Fei — AI product work and portfolio evidence

- Public portfolio: https://liangfei.dev/
- Useful patterns: clear product/problem identity, ownership boundary, shipped artifacts, public product or repository links, and outcome-oriented case structure.
- Adaptation rule: keep the upload resume semantic and single-column; use one verified portfolio link for deeper product cases. Describe user problem, candidate decision, collaboration boundary, shipped state, and measured result.
- Do not copy: product claims, audience numbers, or growth metrics without the same measurement basis and ownership evidence.

## Ovilia / Wenli Zhang — front-end work as public proof

- Public CV source: https://github.com/Ovilia/cv
- Useful patterns: explicit front-end role positioning, public work samples, and code or product artifacts that let readers verify capability.
- Adaptation rule: surface a small number of current, role-relevant public links; keep the PDF reading order independent of the web presentation.
- Limitations: the example is older and its web layout is not an ATS upload contract.

## Cross-example rules

1. Evidence is stronger than decoration: link only artifacts the candidate owns and may disclose.
2. Contribution boundaries create credibility: distinguish led, owned, implemented, coordinated, and team outcomes.
3. Measurements require scope: preserve baseline, population, time window, environment, and benchmark-versus-production status.
4. Role identity should be immediate: headline and first evidence blocks should establish the target function and domain.
5. A portfolio complements the resume: it does not replace a parseable, semantic, single-column PDF.
6. Examples never authorize candidate claims. Company research and public resumes affect structure and emphasis only.
